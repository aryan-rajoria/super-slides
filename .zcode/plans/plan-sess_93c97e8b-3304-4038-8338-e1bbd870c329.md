# data-model.pptx — plan

Professional (non-pixel) companion deck in `nano-super-slides-v5/`, built on the existing pptxgenjs pipeline but with zero sprites — pure native text/shapes, crisp Segoe UI headings instead of bitmap PNGs.

## Theme — light corporate
- Background off-white `#FAFAF8`, ink `#16181D`, muted `#5F6470`, hairlines `#E2E4EA`, single accent **indigo `#304FFE`** (+ tint `#E8EDFF`)
- Verdict chips restyled: COPY green · TRANSLATE indigo · OVERLAY amber · NO SURFACE gray; harness identity = small colored dots/labels (claude amber, codex green, opencode blue, pi purple) only where the matrix needs them
- Furniture: uppercase indigo kicker + 24pt title + hairline, Consolas page counter; white cards with 1px borders, accent left-bars; **no voxels, no hard shadows, no PNGs**
- Fonts: Segoe UI / Consolas (system, as today)

## Slides (14)
1. **Cover** — "The Data Model" · register once, map every team · flat indigo geometry
2. **Two layers** — series map: index / org model / schema / features×10, what each answers
3. **The one correction** — full-parity verdicts vs minimum verdicts; core vs optional overlay (skills = COPY in all four; overlay only buys extras)
4. **Minimum-verdict matrix** — the 10×4 grid with restyled chips (the centerpiece)
5. **Universal envelope + versioning** — registry-owned fields; version lives in 4 places; only bundles self-update; lockfile
6. **Org model · join points** — Area → Functional unit → Team M:N Project (existing tables as stubs)
7. **Org model · new dimensions** — open `harness` table (seeded ×4), `surface` ×10, `harness_surface_capability` (matrix as data), `surface_field` catalog
8. **The field catalog** — core / extras / spec tiers → registration form + validation + emitters
9. **Setup resolution** — most-specific-wins hierarchy + worked example (Engineering → Backend → payments-api → payments-core)
10. **Artifact registry** — `artifact` + `artifact_harness_target`; core_payload vs overlay; version seal
11. **Feature registration** — lifecycle required→approved→installed→pinned→retired; `v_lockfile_export`
12. **ER diagram + the four questions** — boxes/connectors + the queries the model answers
13. **Feature-doc pattern** — skills example: spec 6 fields / Claude extras / Codex `openai.yaml` / OpenCode metadata, tiered core/extras/spec
14. **Closer** — 2026-10-21 OpenCode v2 + Pi verified corrections, deliverables, next steps (deck v1-shape revision, JSON schemas optional, seeding the field catalog)

## Build & gate
1. Write `build_dm.js` (content inline; reuses global pptxgenjs via `NODE_PATH=$(npm root -g)`; no manifest/sprite step) → outputs `data-model.pptx`
2. `verify_dm.ps1` — PowerPoint COM check: 14 slides, non-empty (copy of verify_v5 with filename/count changed)
3. `export_pngs_dm.ps1` — COM export to `render-dm/slide-NN.png` (separate folder; existing `render/` untouched)
4. Visual gate: render all 14 pages, single `presentations:visual-judge` pass over them, fix loop until clean (qa_scan_v5.py is pixel-theme-pinned and is intentionally not reused)
5. DEVLOG v5.4 entry + memory update

Built directly (single cohesive script; no subagent split needed), with the visual-judge agent as the acceptance gate.
