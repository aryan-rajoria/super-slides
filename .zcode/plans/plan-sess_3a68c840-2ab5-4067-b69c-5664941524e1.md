## 2. The topic-card contract (enforced by code)

Every topic (e.g. "Skills", "MCP servers") renders as a card with the **same 6 fixed rows, same order, same styling** — only content and harness accent differ:

- **WHAT** — one plain-English line (readability ask)
- **WHERE** — paths & scopes, mono (e.g. `.claude/skills/` · `~/.claude/skills/`)
- **FORMAT** — manifest/format (e.g. `SKILL.md` + YAML frontmatter)
- **MANAGE** — CLI/install commands (e.g. `claude mcp add … -s user`)
- **AUTO-UPDATE** — verdict + mechanism on **every** card: skills (Claude: file-drop, none — only plugins auto-update, opt-in per marketplace), MCP (no harness auto-updates; registry/lockfile is the answer), subagents/hooks (file-drop), plugins (Codex `marketplace upgrade`, OpenCode `plugin update` + per-version skill catalog cache, Pi `pi update`), etc.
- **REGISTRY VERDICT** — chip: `COPY-AS-IS` (e.g. MCP `mcpServers` JSON into Pi) / `TRANSLATE` (JSON→TOML for Codex MCP) / `OVERLAY` (portable core + harness extension fields, e.g. Skills) / `NO SURFACE` (Codex+Pi LSP, Codex statusline, Codex custom tools) + one-line why
- plus a small **EMISSION** mono block: the concrete registry fields for this artifact×harness (from `design-unified-registry.md` §3–§4), e.g. `install.claude-code = copy → .claude/skills/<n>/ · scopes: project|user|enterprise`

One shared `topicSlide()` factory in the builder generates all 20 harness slides — layout is pixel-identical by construction; a pre-build schema check validates every content entry has all row keys.

## 3. Readability overhaul (per your feedback)

- **Pixel font only for headings**: kickers, slide titles, cover/closer titles stay bitmap sprites (same pipeline). **All body text becomes native Segoe UI** (labels, values, verdict chips, descriptions) at a minimum ~11–12pt with more card padding and whitespace; Consolas mono is kept **only for true code** (paths, config keys, CLI, JSON). The letter-spaced caps bands get dialed back to Segoe UI semibold.
- Shorter lines, plainer language, the WHAT row on every card, and slide 2 explicitly teaches the notation before the chapters start.

## 4. Content sourcing (corpus-only)

- 4 parallel extraction subagents (one per harness; scope-fenced read-only on `agents-unified-registry/`) each produce a `content-<harness>.json` following the exact card schema above, drawn from `claude-code.md` / `codex.md` / `opencode.md` / `pi.md` + `design-unified-registry.md` §3–§4 + `security-trust-model.md` §2 (Claude exec policy lives there). UNVERIFIED-flagged facts stay out or get marked.
- Absent surfaces get an honest `NO NATIVE SURFACE` card with version/date ("as of codex v0.163.0, 2026-10") — absence is registry data. No new web research.
- I (main thread) own `build_v5.js`, `gen_sprites_v5.py`, and merging the content JSONs — nobody else edits source, per the sub-agent playbook.

## 5. Build pipeline (copy-adapt from v4)

1. `nano-super-slides-v5/gen_sprites_v5.py` — new TEXTS (25 kickers/titles/cover only; far fewer bitmap texts since body is now native), reuses v1 `gen_assets.py` font + v4 voxel cell functions; regenerates cubes/runner/machine art into `v5/assets/` + manifest. Built-in `verify()`.
2. `nano-super-slides-v5/build_v5.js` — pptxgenjs, same `P`/`ACC` theme constants and card/shadow/chip helpers, new `topicSlide()` factory + parametrized page counter (fixes v4's hardcoded `/ 13`); fonts per §3.
